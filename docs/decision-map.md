# Where AI decides, and what checks it

Every model call the app makes goes through `backend/gateway/gateway.py` under a `purpose`; `backend/gateway/catalog.py` says which model each purpose uses. This map documents what is checked today. It is not how evals are picked: those come from graded failures. Paths below are under `backend/`. Counts are as of 2026-10-20 (main e7739ee).

Every picture is drawn on OpenAI's own API, even when Azure answers the text and vision calls. With no `OPENAI_API_KEY`, each picture fails and says so (`gateway/openai_adapter.py`, `adforge/settings.py`).

How a decision can be checked:

- **Test**: the suite in `tests/`. Every test there runs on a scripted fake model (`gateway/fake.py`), so tests prove the wiring and code guards, never the quality of a real answer.
- **Eval**: a real model's answers scored against Julian's (the project owner's) grades, run by hand. Julian's grades of a round's ads and clips are counted by `evals/round_export.py` and `evals/results.py`.
- **Judge**: another model checks the output inside the app.
- **Guard**: code refuses or caps a bad answer. **Prompt only** means the rule is just text in the prompt.

Harm if a decision is quietly wrong: **broken ad** (the owner sees a bad ad), **paid remake** (the owner pays for a useless remake), **unseen** (nothing visible).

The rule judges: `evals/ai_checks.py` is scored against 208 graded cases in `evals/rule_cases.json` (20 plan-level, the rest B-roll scenes), and `evals/run_rule_checks.py` runs free code checks on a saved run. Re-running the cases tests the judges, not a new planner or prompt. The rule judges ask under `rule_eval`, which is not a catalog purpose: their calls are not recorded.

Biggest blind spots today: the fact check is not measured. Talking-scene starting pictures and the before-picture have no judge. The video reader and video transcripts have no eval, yet the planner and the fact check take what they keep as the shop's own words. The clip judge still misses failures and fails good clips (round 6, above), and the fixing agent trusts it, so a wrong pass ships a bad clip. The owner's yes to an owner part is the producer model's call. Whether a typed answer to a fix plan means yes is the decider model's call: code reads a tapped yes itself, and a typed one only for a plan shown before it (`agents/routing.py`).
